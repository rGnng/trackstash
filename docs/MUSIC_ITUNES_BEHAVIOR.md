## 1. 导入时的命名规则【实测】

用 ffmpeg 生成静音 m4a，用 TrackStash 的写标签函数写入标签，然后加入 Music，读取它生成的路径。

| 标签情况 | Music 结果 |
|---|---|
| 标题含 `.`（`O.O.H`、`Mr. Hyde`） | 原样保留，扩展名正常 |
| 标签含 `/` | 替换为 `_`（`w/FullMoon` → `w_FullMoon`） |
| 艺术家含 `:`，专辑含 `*` `?` | 替换为 `_` |
| 标题含弯引号 `’ “ ”` | 替换为 `_` |
| 标题含方括号 `[ ]` | 保留 |
| 艺术家末尾 `.` | 目录名末尾换成 `_`（`V.A.` → `V.A_`） |
| 艺术家/标题末尾空白 | 删除 |
| 无曲目号 | 文件名无前缀 |
| 曲目号 0 | 无前缀 |
| 碟号与碟数 | 见第 1.1 节 |
| 合辑（cpil 为 1） | 进入 `Compilations/<专辑>/` |
| 标题以两个点结尾 | `here..` + `.m4a` = `here...m4a` |
| 扩展名大写 `.MP3` | 保留大写 |
| 反斜杠 `\` | 替换为 `_` |
| 专辑为空 | 目录 `Unknown Album` |
| 没有专辑艺术家 | 用艺术家作为目录名 |
| 标题为空 | 文件名用源文件名（去掉扩展名） |
| 保留名 `CON` `con` | 目录 `CO_`（最后一个字符换成 `_`，统一大写） |
| 保留名 `AUX` `PRN` `NUL` `COM1` `LPT1` | `AU_` `PR_` `NU_` `COM_` `LPT_` |
| 完全相同的两首（E20/E21） | 第二首被静默丢弃（去重） |


### 1.1 碟号与碟数的全部组合【实测】

10 张专辑各放入一首曲目，加入 Music 后读取实际路径：

| 碟号 | 碟数 | 结果 |
|---|---|---|
| 1 | 2 | `1-01` |
| 空 | 2 | `01` |
| 空 | 空 | `01` |
| 1 | 空 | `1-01` |
| 0 | 2 | `01` |
| 空 | 1 | `01` |
| 1 | 1 | `01` |
| 2 | 空 | `2-01` |
| 3 | 2 | `3-01` |
| 0 | 空 | `01` |

归纳：

- 碟号为空或 0：不加前缀（不论碟数）。
- 碟号 1 且碟数为 1：不加前缀。
- 碟号 1 且碟数为空或大于 1：加 `1-`。
- 碟号大于等于 2：加前缀（不论碟数）。

### 1.2 之后加入其它碟不会改名【实测】

在上述 10 张专辑里各加入一首"碟号 2、碟数 2"的曲目：

- 原有 10 首的路径**全部不变**。
- 新曲目为 `2-02 ...`。

结论：碟号前缀只由每首曲目自己的碟号和碟数决定，与专辑里其它碟无关。

## 2. 前导空白【实测】

- 专辑艺术家 `" LeadArt"` → 目录 `_LeadArt`
- 专辑艺术家 `"  TwoSpace"`（两个前导空格）→ `_ TwoSpace`：**只替换第一个字符**
- 专辑 `" EDGE SP F"` → `_EDGE SP F`
- 无曲目号的标题 `" NoTrack"` → 文件名 `_NoTrack.m4a`
- 有曲目号的标题 `" LeadTitle"` → `01  LeadTitle.m4a`（保留，不替换）
- 内部连续空格保留（`01  LeadTitle`、`Sturm  und Drang`）
- 目录名以 `.` 开头：`.banbanshi` → `_banbanshi`（首个字符替换为 `_`）

## 3. 长度上限【实测，部分推断】

- ASCII 目录名：264 字符 → 截到 253。
- 含 NFD 的目录名（`é` 在 Music 中存成 NFD）：`EDGE` + 200 个 `é` → 只保留到 252 UTF-16 码元。
- 含 CJK 的目录名：`EDGE` + 100 个 `あ`（104 码元）→ **不截断**。
- 文件名（有曲目号前缀）：标题截到 246 个字符（`253 − "01 " − ".m4a"`）。
- 文件名：`あ` + 256 个 `a`（超限）→ 截断后扩展名丢失，变成 `…aaaaa.m`。
- 文件名：84 个 `あ`（252 字节）→ 扩展名丢失（Music 的 bug）。
- 文件名：70 个 `あ`（未超限）→ 扩展名保留。
- 无曲目号的 260 个 `n` → 截到 253，扩展名保留。

**推断**：Music 的上限按 UTF-16 码元计算为 253；多字节超限时，它按字节再截一次，会切掉扩展名。

## 4. 修改标签后的行为【实测】

Music 对已入库的曲目修改标签，会**立即**改名或移动文件夹，并把修改写回文件。

| 修改 | 结果 |
|---|---|
| disc_count 空 → 1 | `1-01 Memory.m4a` → `01 Memory.m4a` |
| 碟号 1 → 6 | `01 Memory.m4a` → `6-01 Memory.m4a` |
| 曲目号 7 → 9 | `07 Neon.m4a` → `09 Neon.m4a` |
| 标题改动 | 文件名改变 |
| 合辑标志 false → true | 移入 `Compilations/` |
| 专辑艺术家改动 | 文件夹改变 |

写回验证：改合辑标志和标题后，文件里的 `cpil` 和 `©nam` 都已更新。

## 5. 加入新碟【实测】

- 专辑 `EDGE 13` 中已有 `6-01 Memory.m4a`；加入一首碟号 5 的曲目。
- 结果：`6-01 Memory.m4a` **不变**；新文件 `5-02 Five Two.m4a`。
- 结论：碟号前缀是逐曲目决定的，加碟不会触发已有文件改名。

## 6. 外部修改不会被 Music 感知【实测】

- 用 mutagen 直接把文件的 `cpil` 改为 false、标题改为 `WB Title External`。
- Music 中的值仍是 `compilation=true` 和旧标题。
- 结论：**Music 不会自动重新读取被外部修改的文件**。库和文件会分叉，直到重新导入。

## 7. 标签读取：Music 与 mutagen/TrackStash 的差异

### 7.1 合辑标志（cpil）【实测】
- MP4 `cpil` 的数据类型为整数（type 21）。
- 值 `0x01` → Music 为合辑（677 首）。
- 值 `0x00` → 非合辑（668 首）。
- 值 `0x30`，即文本字符 `'0'`（757 首）→ **Music 读为 false**。
- mutagen 的 `bool(ord(data))` 把 0x30 当成 True，这是 TrackStash 读取错误的原因。
- 验证：对 10 首 0x30 文件删除后从备份重新导入，Music 仍为 false，路径不变。
- 当前规则（TrackStash）：只有值为 1 才是合辑。

### 7.2 缺失字段与多值字段【实测】

| 情况 | Music 的处理 | TrackStash |
|---|---|---|
| 缺少艺术家帧（mp3 无 TPE1，只有 TPE2） | 用专辑艺术家 | 生成路径时用专辑艺术家 |
| 缺少标题帧（mp3 无 TIT2） | 用文件名（去掉扩展名） | 同 |
| 多个 genre（`©gen` 为两个值） | 取最后一个（11 首验证：`Symphonic Rock`, `Symphonic Metal` → `Symphonic Metal`） | 取最后一个 |
| 年份带杂质（`24-0`） | 显示 `24`（取前面的数字） | 同 |
| 年份为 `2021-08-14` | 显示 `2021` | 同 |

**实现位置**：读取层（`read_metadata`）保留文件的原始值，避免编辑标签时把值改掉；Music 的取值规则在生成路径时应用（`template_values`）。

### 7.3 年份格式

iTunes 库把年份存为 4 位（`2021`），文件里常见完整日期（`2021-08-14`）或带杂质的两位年份（`24-0`）。Music 只显示前面的年份部分，TrackStash 生成路径时按同样规则取值。

### 7.4 mp3 曲目号【未解决】
- 专辑 `SO MANY COLOURS` 的 7 首 mp3，ID3v2.3 中 TRCK 为 `3`、`7` 等，同时有正确的 ID3v1 曲目字节。
- Music 读到的曲目号为 0，文件名没有前缀。
- 原因未知。其他 mp3 的曲目号 Music 能正常读取。

## 8. 重新导入的结果【实测】

- 对 97 首不一致的文件（年份、genre、标题、艺术家、曲目号）做了删除（Move to Trash）+ 从备份重新导入。

## 8.1 用 Music 规则整理现有库的 dry-run 结果

用最终的 TrackStash 规则（不移动任何文件）对 20,829 首重新生成路径，与库里的实际路径逐一比较：

| 结果 | 数量 | 比例 |
|---|---|---|
| 完全一致 | 17,918 | 86.0% |
| 不一致 | 2,911 | 14.0% |

不一致的构成：

| 类别 | 数量 | 性质 |
|---|---|---|
| iTunes 文件名没有曲目号（源文件名） | 1,025 | 库是历史快照，iTunes 当初没有重命名 |
| 其他（碟号 1 且碟数空的少数专辑、源文件名等） | 993 | 见下 |
| 目录名大小写不同 | 357 | iTunes 目录名是历史快照 |
| 标题与当前标签不同 | 340 | 标签改过但 iTunes 没有重命名 |
| 源文件名含"艺术家 - 标题"或 `×` | 196 | 从未被 iTunes 整理 |

**结论**：这 2,911 首几乎都是"iTunes 没有按当前标签重命名"的历史遗留，不是 TrackStash 的规则错误。TrackStash 整理后会按当前标签统一命名。

## 8.2 删除后重新导入的抽样验证【实测】

从 2,911 首不匹配里按类别各抽 3 首（共 15 首），做"同盘备份 → 从 Music 删除并移除文件 → 从暂存目录重新导入 → 读回路径"的完整实验：

| 类别 | 重新导入后的路径 | 与 TrackStash 规则 |
|---|---|---|
| 源文件名无曲目号（3 首） | 按标签重命名为 `04 GROOVE IN LUCKY(Extended Mix).m4a` 等 | **全部一致** |
| 其他（碟号、`艺术家 - 标题`）（3 首） | `82 Divine Heaven.m4a`、`03 Starlight.m4a`、`1-01 Intro.m4a` | **全部一致**（含碟号 1、碟数为空时加前缀） |
| 标题旧值（3 首） | 按当前标签重命名，`[MUSIC SELECT]` 变成 `_MUSIC SELECT_` | **全部一致** |
| 源文件名含艺术家（3 首） | `04 Read an Emotion.m4a` 等 | **全部一致** |
| 目录名大小写（3 首） | 文件名按标签整理，但目录仍是旧的 `Holtunes`、`SPACELECTRO` | **不一致**（仅目录大小写） |

汇总：**15 首中 12 首与 TrackStash 规则完全一致**，2 首仅目录大小写不同，1 首完全没变（也是大小写）。

### 结论

1. 其余 2,911 首的不匹配，确实是 iTunes 没有按当前标签重命名，而不是规则差异。重新导入后 Music 会按标签整理成 TrackStash 规则预测的路径。
2. 唯一稳定不可复现的差异是**目录名大小写**：旧目录已经存在，大小写不敏感的文件系统会复用它，Music 不会只为了大小写去改名。这与第 10 节以及 `FILENAME_COMPATIBILITY.md` 的记录一致。
3. 因此，把整库交给 TrackStash 整理后，与 Music 的差异只剩"目录名大小写"这一类，以及 iTunes 尚未整理的历史文件名。

## 9. iTunes 库快照（历史，不作为规则）【历史】

基于 20,829 首的只读导出：

- **碟号前缀**：由每首自己的 `disc_count` 决定。`disc_count = 1` 的 8,629 首全部无前缀；`disc_count ≥ 2` 的大多数有前缀；`disc_count` 为空时 1,887 有前缀 / 332 无前缀。
- **合辑**：库中 870 首为合辑。
- **目录大小写不一致**：约 340 首，同一文件夹内标签拼写一致，但与目录名大小写不同，说明目录名是旧快照。
- **来源文件名未被整理**：约 1,070 首的文件名仍是源格式（如 `A-One×AXEL.K - …`）。
- **标题与当前标签不同**：约 351 首，说明改标签后 iTunes 没有重命名。

这些是历史快照，不代表规则。我们的目标是 Music 当前的行为，不是复现旧数据。

## 10. 文件系统相关【实测】

- **exFAT（音乐盘）**：从 APFS 复制 NFC 名字过去，磁盘上存为 NFD。
- **exFAT 查找**：NFC 和 NFD 两种路径都能找到同一文件，读取内容正确。
- **exFAT 允许** `: * ? " < > |`、末尾空格和点（能创建），所以这些替换是 Music 的规则，不是文件系统强制的。
- **大小写不敏感**：`CaseTest` 和 `casetest` 是同一个文件。
- **APFS**：按写入原样保存，查找时 NFC 和 NFD 都能找到。
- **Music 对 NFD 输入**：保存的也是 NFD（目录和文件）。

## 10.1 只改标签大小写时 Music 不改目录名【实测】

- 曲目的专辑艺术家为 `Edge Artist`，目录也是 `Edge Artist/…`。
- 在 Music 中把专辑艺术家改成 `EDGE ARTIST`。
- 结果：标签值变为 `EDGE ARTIST`（也写入了文件），但目录仍是 `Edge Artist/…`，文件位置不变。

原因：大小写不敏感的文件系统把两个名字视为同一个目录，Music 认为目标已存在，不做重命名。

TrackStash 的处理：保持不改目录名（与 Music 一致），但写入数据库前解析并记录磁盘上的真实拼写（`resolve_disk_path`），避免数据库路径与文件系统不一致。

## 11. AppleScript 操作注意事项【实测】

- `location of 引用` 在搜索结果上会报错（-1728）；必须用 `file track id N` 或 persistent ID 取得引用，再分两步读取（先 `set L to location of t`，再 `POSIX path of L`）。
- 嵌套写法 `POSIX path of (location of t)` 在新加入的曲目上会失败。
- 删除曲目时 Music 弹出 `Keep File` / `Move to Trash` / `Cancel` 确认框，脚本会阻塞。必须在脚本外用 System Events 点击，否则 AppleScript 会超时。
- 中断脚本后，确认框会残留。残留框要点 `Cancel`，不要点 `Move to Trash`。
- 批量读取（`every track of library playlist 1`）可用，但耗时较长，要加 `with timeout of N seconds`。
